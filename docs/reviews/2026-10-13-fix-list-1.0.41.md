# Fix list for release 1.0.41

This list holds every finding from the 2026-10-13 code-quality review of 1.0.41 (`20e0b24..31855b8`) that needs a fix. The findings were triaged by a second opinion, and the save pipeline got its own design review.

IDs are the review's: B-n for bugs, Q-n for quality findings. Bugs B-13 and B-14 are new from the design work, and B-15 and B-16 were found while fixing the save pipeline. Each item says what is wrong, where, the plainest fix that meets CLAUDE.md, and the effort (S = a few lines, M = a function or a test fixture). The findings left alone are listed at the end.

Order: the save pipeline first, then the bugs, then the smaller cleanups.

---

## 1. OneNote save pipeline (next focus)

### The design decision

The question was whether the two-writer save pipeline is the proper design, and what the proper fix is rather than a patch. A design review traced the git history and prototyped the options.

**What each stage protects:**

| Stage | What it is for |
|---|---|
| **Graph planner** (`onenote_patch.py`, `2f956be`) | The single alignment of the page against the note. It emits per-element commands and refuses any plan whose simulation does not reproduce the note. This protects three things: content is never lost, element IDs are kept (a replaced item duplicates on a phone), and an unchanged image is never mentioned. |
| **Blank-line removal** (`b4fe47e`) | Graph cannot target a bare `<br/>`. It is removed natively, *before* the Graph commands. This is the template the list work copied. |
| **Native list write** (`31855b8`) | Graph cannot move list items. A Graph rewrite recreates them, and their formatting is lost. The native writer reparents the *existing* objects, so items keep their identity and rich text (verified byte-identical). |
| **Media split** (`list_changes`) | The native writer can only encode rich text, and media can only enter through Graph. This is the one place the two writers' capabilities are reconciled. |
| **Re-plan after the native write** (the recursion) | It is needed: the new elements only get Graph IDs after the native revision. |
| **Graph "relevel"** | Never sent to Graph. It builds the native writer's target inside the planner's single alignment. |

**Verdict:** the **phases are right**. Each is forced by a measured API constraint. What is wrong is the **hand-off between the two writers**:
1. The planner's notion of "same element" ignores list structure (B-1).
2. The native target drops media instead of leaving Graph a place for it (B-13).
3. `insert()` anchors on list IDs that Graph cannot locate (B-13).
4. The shape: commands are re-parsed, and `write_body` recurses with a flag (Q-3).

**The options:**

| Option | Verdict |
|---|---|
| A 5-line rule in `update()` | **Workaround.** It patches one consumer of a wrong definition. 14/17 cases pass; "indent + append" fails. |
| A redesign that decides the native phase first, from structure | **Over-design, and incomplete.** Building the native target *is* an alignment, so the redesign duplicates the planner. It also leaves points 2–3 open. |
| **Structure-aware sameness + list anchors last + media placeholders** | **The proper fix.** Built and proven through the real native writer (`NativeSaveTests`). Two corrections to the prototype came from that path. (1) An *empty* `<p>` placeholder becomes a blank line, which Graph exports without an ID, so the placeholder holds one no-break space. (2) `blank_lines.py` cannot remove a blank line beside a list, so the native writer removes the save's blank lines whenever it runs, and always removes one beside a list. |

**How a future native-only structure fits:** the planner gains one predicate in `_Planner.native` ("this needs the native writer") and the native writer gains one encoder. The phase order, target derivation, placeholders, re-plan and journal recovery stay as they are.

**To confirm once on a disposable page:** that OneNote exports a native paragraph holding one no-break space with a generated ID, and that Graph accepts `replace p:<id>` with a table or image.

**Known edge, left as it is:** if Graph refuses right after the native revision, the page keeps the list change. The next save normally finishes the job. But when the planner had paired an edited paragraph with the new media, the half-written page can differ from the draft enough that the next save asks for a conflict review. Nothing is lost.

### The items

- [x] **B-1 / Q-1: the planner's "same element" ignores list structure** (S). *Done as below.*
  - **Wrong:** `onenote_patch.text()` / `identity()` render a node out of context, so `<li>Two</li>` and `<ul><li>Two</li></ul>` compare equal. Indenting or outdenting a plain bullet is refused ("could not preserve this page's content"), and so is "indent + append".
  - **Where:** `plugins/org.note-note.onenote/onenote_patch.py`:
    - `identity` (≈:123)
    - `sequence`'s unchanged-prefix shortcut (≈:228)
    - `update` (≈:388)
    - `preserve_projected` (≈:579, :586)
  - **Fix:** define sameness once, then use `unchanged()` in all four places:
    - `role(node)` is the tag for `ul`/`ol`/`li`, `""` otherwise.
    - `identity(node) = (role, text_key(text))`, with `None` still meaning a separator.
    - `unchanged(old, new)` means same role and same text.
  - In `update`, a role change inside a changed span tries `relevel_list([old], [new])`.

- [x] **B-13 (new): a table or image placed between two list halves can never be saved** (S). *Done, with the corrections in the design decision above.*
  - **Wrong:** the native target *drops* `img`/`object`/`table` instead of leaving Graph a place for them. So:
    - "Table splits a list" fails with "OneNote did not return the requested list layout".
    - "Table before a list mid-outline" first writes an **empty native revision**, then fails the same way.
  - **Where:** `list_edits.py:211` (`list_changes`); `onenote_patch.py` `_Planner.insert` (≈:326-353); `onenote.py` `write_lists`
  - **Fix:**
    - A paragraph holding one no-break space takes each table or image's place in the native target, and the Graph phase replaces it.
    - `insert()` anchors on a list's ID only when nothing else exists: `continue` after a failed list-boundary attempt, and a last loop for list-only anchors. "Table before a list" is now Graph's alone.
    - The guard against an empty native revision is not needed: with the two changes above, no save asks for one.

- [x] **B-15 (new): a list made in a table cell could not be saved** (S). *Done.*
  - **Wrong:** since `31855b8`, any command whose content holds a list went to the native writer, which moves a table as one element and cannot write inside a cell. Turning a cell paragraph into a list failed with "Could not save the lists…". The `needs_native` stub hid it.
  - **Fix:** `_Planner.native` leaves commands inside tables to Graph, and counts only lists outside tables.

- [x] **B-16 (new): a blank line beside a list could not be removed** (S). *Done.*
  - **Wrong:** `blank_lines.py` names a run by its neighbours' IDs, and a list's ID names its outline or parent item, never a sibling of the blank line. Deleting a blank line after a list failed with "The blank lines changed in OneNote".
  - **Fix:** a blank line beside a list goes to the native list writer, which rewrites the outline (`_Planner.native`).

- [x] **Q-2: the save tests never run the native phase** (M). *Done.*
  - **Built:** `NativeSaveTests` holds the page as OneNote's native objects, with only the transports faked (`native_page`, `graph_page`, `RevisionService`). The five list-topology tests moved there, and `SaveTests` routes as production does.
  - **Wrong:** `merge_selftest.SaveTests` stubs `needs_native` for the whole class (`merge_selftest.py:1054`). The tests at :661/:687/:704/:743 assert Graph operations that production never sends, and the suite stayed green while B-1 failed.
  - **Fix:** a real-path fixture, built together with B-1:
    - `graph_page(markdown)` builds the Graph HTML together with the matching revision state.
    - A `write_lists` fake runs the real `list_edits.plan`, applies the revision, exports it as Graph does, and runs `list_indents.restore`.
    - Cases: the 17 relevel cases, the 9 mixed edits (indent + table beside + blank line removed …), recovery between the two writers, and unchanged rich-text objects staying byte-identical.
    - Remove the `needs_native` stub.

- [x] **B-14 (new): a nested numbered list in OneNote is read flat and saved flat** (S). *Done: `Converter.block` carries the indent column, not a level count. Existing pages with nested numbered lists now open with their nesting.*
  - **Wrong:** `Converter.list_item` indents a sublist by `"  " * depth`. Under a `1.` item, CommonMark needs the marker's width (3), so the shared parser reads the sublist as top-level. This is why "numbered lists work" looked true.
  - **Where:** `plugins/org.note-note.onenote/onenote_md.py:367`
  - **Fix:** indent by the parent marker's width, as the editor's own writer does (3 under a number). Add a round-trip test.

- [x] **Q-3 + shape: `write_body` recurses with a flag, and the routing re-parses commands** (M; after the items above and their tests). *Done. Command contents stay strings, parsed once in `_Planner.native`.*
  - **Where:** `onenote.py:1693-1759`; `list_edits.py:176-213`
  - **Fix:**
    - `_Planner.finish()` computes `Plan.native`, the page the native writer must produce first, using today's `needs_native` rule on node lists, before serializing.
    - `write_body` becomes linear: plan → native write, read back, verify, re-plan once → blank lines → PATCH.
    - Delete `needs_native`, `list_changes`, the recursion and `lists_saved`.
    - A local `as_note(html)` replaces the four identical `html_to_markdown(...)` calls.
  - No behaviour change.

- [x] **Docs: say who does a relevel** (S). *Done. Also: `tests/selftest.py` now runs `list_edits_selftest.py`, which only CMake ran.*
  - `docs/engine-notes.md:619-621` still describes a relevel as a Graph replace; it is the native writer's.
  - Move the OneNote save internals from `docs/editing-tools.md:143-151` there too (**Q-26**).

- [x] **Q-4: the revision service is in the read path of every list page** (S now, M next) *Done: the page opens read-only with a reason; the page check reuses the last read's levels while Graph's HTML is unchanged; the revision travels explicitly.*
  - **Wrong:** `read_page` calls `restore_list_indents` (`onenote.py:1354-1373, 1389`) on every open *and* every once-a-minute check of the open page (`page --check`). That is about 6 requests per check, about 360 an hour, against OneNote's 350-an-hour budget (`onenote.py:58`). A `WebError` there also stops the page from opening.
  - **Fix now:** catch `WebError` around `restore_list_indents` in `read_page`. The page then opens read-only with a reason.
  - **Fix next:** the check compares Graph's HTML with a hash kept with the journal base, and restores native levels only when the page changed. Pass the revision explicitly instead of the hidden `result["_list_revision"]` key.

- [x] **Q-5: "open the page's revision cell" is written three times, plus once in `blank_lines`** (M) *Done: `open_page_revision`; `blank_lines.remove` takes the revision.*
  - **Where:** `onenote.py:1358-1373` (`restore_list_indents`), `:1653-1671` (`write_lists`), `:1635-1645` (`remove_blank_lines`); `blank_lines.py:121-125`. The copies already drift: `remove_blank_lines` skips the cached `clientId`.
  - **Fix:** one `open_page_revision(page_id, …) -> (session, cell, state)`, used by all three.

- [x] **Q-8: about a dozen bare native property IDs** (S) *Done, named after [MS-ONE] as Apache Tika lists them.*
  - **Where:** `list_edits.py:247-331` (`0x1400342E`, `0x14003467`, `0x44000811`, …)
  - **Fix:** name them in the file's own style, beside the roughly 30 it already names. Leave the font and the module split.

- [x] **Q-9: the literal `0x60019` is repeated where `list_edits` calls it `GROUP`** (S) *Done: `GROUP` lives in `blank_lines.py` beside `ELEMENT`.*
  - **Where:** `blank_lines.py:75`; `list_indents.py:14, 40`
